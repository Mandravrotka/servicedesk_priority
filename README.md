# servicedesk-priority

Система автоматической расстановки приоритетов заявок в сервисдеске. Автоматически анализирует обращения, определяет их приоритет на основе контекста и базы примеров, и предоставляет удобный веб-интерфейс для управления настройками системы.

## Интеграция с Redmine и обратная связь

Система включает собственный экземпляр Redmine, который разворачивается автоматически при установке, всё работает внутри изолированного контура.

### Как это работает
1. Система автоматически получает новые задачи из развёрнутого проекта Redmine по его уникальному идентификатору.
2. Каждая заявка обрабатывается LLM, которая анализирует текст, контекст и базу примеров, определяя уровень срочности по шкале от 1 (критический) до 6 (пожелание).
3. Результат сохраняется в Redmine, а также логируется в базу данных.

### Механизм обратной связи
Система постоянно улучшает точность предсказаний за счёт обучения на основе ваших действий:
- **Корректировка:** Если приоритет был определён неверно, оператор может вручную исправить значение в Redmine. Эта корректировка автоматически сохраняется как новый обучающий пример.
- **Дообучение:** При следующей обработке похожей заявки система учтёт исправление и с большей вероятностью выберет верный приоритет.

## Стартовые данные для тестового запуска

Для тестирования система уже содержит готовые конфигурации, которые можно загрузить через интерфейс:
- **Промпты:** находятся в `setup/prompts`.
- **Примеры приоритетов:** расположены в `setup/examples`. 

##  Поддерживаемые модели

- **Основная LLM:** система совместима практически с любой современной моделью. Просто выберите нужного провайдера в настройках (Ollama, OpenAI, Anthropic, DeepSeek, Groq и др.).
- **Модели эмбеддингов:** для векторного поиска подходят:
  - Локальные через Ollama: `mxbai-embed-large`.
  - Облачные провайдеры: OpenAI - `text-embedding-3-small`, Gemini - `text-embedding-004` и аналоги.

## Запуск

1. **Склонируйте репозиторий и перейдите в папку:**
   `git clone https://github.com/Mandravrotka/servicedesk_priority`
   `cd servicedesk_priority`

2. **Настройте `.env` файл:**
    Создайте копию файла `.env.example` под именем `.env`

3. **Запустите систему:**
   `docker compose up -d`
   > При первом запуске система автоматически создаст конфигурацию, развернёт экземпляр Redmine, подготовит базу данных и активирует все процессы.

4. **Откройте веб-интерфейс:**
   Перейдите в браузере по адресу, соответствующему вашему серверу (например, `http://<ваш-домен-или-ip>`).

5. **Войдите в систему:**
   - **Логин:** `admin`
   - **Пароль:** `admin123`

## ️ Настройка и управление

### Веб-интерфейс
После первого входа перейдите в раздел **Настройки**:
- Через интерфейс вы можете переключать ИИ-провайдеров (основную LLM и модель эмбеддингов).
- Изменить пароль администратора.

### Файл `.env`
Все системные параметры хранятся в `.env`:
- Учётные данные баз данных и пароли
- Ключи доступа к Redmine и Telegram
- Адреса и ключи для моделей
- Переменные окружения для n8n и PostgreSQL

> **Важно:** После изменения любых параметров в `.env` или переключения провайдеров в интерфейсе необходимо выполнить полную перезагрузку проекта. Без этого изменения не вступят в силу.
> Команда для перезагрузки: `docker compose up -d --force-recreate`

### Управление сферами
В разделе **Сферы** вы можете:
- Создавать новые домены обслуживания (привязанные к проектам в локальном Redmine).
- Редактировать системные промпты для каждой сферы.
- Загружать и корректировать базу примеров для обучения LLM.
